# 别再背 netsh 参数了：我给 portproxy 写了个图形界面

> 一个 1180×760 的小窗口，把 `netsh interface portproxy` 的查看、新增、编辑、删除全收进去，附备注、筛选和命令回显。

**源码地址**：https://github.com/2693587744/netsh-ui

## 起因

开发时经常要在 Windows 上做端口转发：把 `0.0.0.0:58088` 转到内网某台机器的 `10.0.9.3:58088`。

能用的命令只有一条：

```bat
netsh interface portproxy add v4tov4 listenaddress=0.0.0.0 listenport=58088 connectaddress=10.0.9.3 connectport=58088
```

问题是：

- 参数名一个都不能错，`listenaddress` 少个字母就是一条报错；
- 想看现在有哪些转发，得再记一条 `netsh interface portproxy show all`，出来是张挤在一起的对齐表格；
- 想删掉旧的一条，得把侦听地址和侦听端口原样再敲一遍；
- 改的时候最烦——portproxy **没有"修改"**，只能先 `delete` 再 `add`，忘了删就会多出一条绑定同端口的规则；
- 隔两周回来，根本想不起 58088 到底转发给谁在用。

这些事一共就三条命令，但每次都要翻历史记录。于是干脆写了个小工具。

## 它长什么样

一个窗口，两个标签页：**端口转发** 和 **命令行输出**。

端口转发页只有一行工具栏和一张列表：

- 左边是「添加转发」，右边是「刷新」，非管理员启动时右边会多一个「以管理员身份重启」；
- 列表列是：类型 / 侦听地址 / 侦听端口 / 目标地址 / 目标端口 / 备注，最后一列是「操作」；
- 每行的操作列就三个小按钮：**备注、编辑、删除**；
- 双击整行等于点「编辑」，不用先选中再找按钮。

新增和编辑都是 430 宽的小弹窗，填五个框就完事，主界面不常驻任何大表单——这类操作一个月用不了几次，不值得占版面。

## 几个真正省事的细节

### 1. 备注存在本地，不污染系统

portproxy 本身不支持备注，`show all` 永远只给你五列干巴巴的地址和端口。

这个工具在旁边挂了一列备注，键是 `方向|侦听地址|侦听端口`（比如 `v4tov4|0.0.0.0|58088`），存在本机 JSON 里，不写进系统、不碰注册表。

存放位置有讲究：

1. 优先读**程序所在目录**的 `portproxy-notes.json`——把整个文件夹拷到另一台机器，备注跟着一起走；
2. 没有就回退到 `%APPDATA%\NetshUi\portproxy-notes.json`。

读到哪一份就写回哪一份。转发被删掉、或者系统里已经不存在了，对应备注会自动清理，不会越攒越多。关窗前还会强制落盘，刚打完字就关窗口也不会丢。

### 2. 改侦听端口时，自动先删旧条目

前面说过 portproxy 没有"修改"。所以在编辑窗口里如果动了侦听地址或侦听端口，工具会先 `delete` 掉旧的那条，再 `add` 新的——避免一条转发变成两条，把端口占住。

### 3. 输入即筛选

过滤框支持按端口、地址、备注模糊匹配，边打边出结果，框里右侧带个 ✕ 一键清空，旁边实时显示"共 N 条 / 筛选出 N 条"。

端口记不住、备注也写不全的时候，输入 `58088` 或者 `测试库` 就够了。

### 4. 每条命令都能看见

底部没有塞一大块输出面板，而是收到第二个标签页「命令行输出」里。

每次操作都会把**真实执行的 netsh 命令**和原始输出回显上去，成功失败一目了然。好处是：出问题时不用猜工具到底干了什么，直接把那行命令复制到 cmd 里就能重放。

### 5. 权限问题不打断操作

`add` / `delete` 必须管理员权限。普通权限启动时，工具不会一上来弹 UAC，而是在工具栏右侧挂一条「以管理员身份重启」，点了就带着参数重新拉起自己。管理员启动时这条入口直接不出现，不浪费像素。

## 技术上有意思的几个坑

工具用 [MewUI](https://www.nuget.org/packages/Aprillz.MewUI.Windows)（Direct2D 渲染的 .NET UI 框架）写，可以编译成 Native AOT 单文件，目标机器连 .NET 运行时都不用装。

踩到的坑比较有代表性：

**坑一：netsh 的输出编码不固定。**
中文系统下通过管道调用 netsh，输出是 GBK；直接 `cmd /c` 调用却是英文；重定向到文件又会变成 UTF-16。所以解码策略是"先按严格 UTF-8 解，抛异常了再回退系统 OEM 代码页"。

**坑二：输出会随系统语言本地化。**
`show all` 的表格有表头文字，但表头是"侦听地址 / 端口"还是 `Listen Address / Port` 取决于系统语言。所以解析器**一律按列位置取值，不认表头文字**——反正这张表永远是四列。

**坑三：自定义单元格的容器会回收复用。**
MewUI 的 GridView 里放按钮那一列要自己实现 `IDataTemplate<T>`。单元格控件会被复用，按钮点击时怎么知道是哪一行？在 `Bind` 时把当前行塞进控件的 `Tag`，点击回调里再从 `Tag` 取。另外 NuGet 版接口的默认成员实现不生效，`IDataTemplate.Bind/Unbind` 必须显式实现，不然列表根本渲染不出来。

**坑四：验证界面别靠截图工具。**
调试时用 P/Invoke 调 `PrintWindow` 把窗口直接画成 PNG 再读图，比截屏靠谱——不受其它窗口遮挡影响。

顺带一提，这个工具的开发过程本身就是"反面教材"：第一版我按 netsh 有哪些上下文就做了 11 个页面（接口、路由、防火墙、无线、DNS、WinHTTP……），结果被自己一句话否掉——**"你不必实现这么多用不着的功能，先把这几个实现"**。

砍到只剩端口转发之后，它才真的变得好用。

## 怎么跑起来

仓库在 https://github.com/2693587744/netsh-ui ，clone 下来直接跑。

环境要求：Windows 10 及以上；自己编需要 .NET 10 SDK。

```bash
dotnet run
```

发布成单文件（不需要 .NET 运行时的版本）：

```bash
dotnet publish -c Release -r win-x64 -p:PublishAot=true -o publish
```

产物里除了 `NetshUi.exe` 只有一个 `.pdb` 调试符号，不需要调试直接删掉。拷到任何一台 Windows 上双击就能用。

## 边界

这工具**不做**通用 netsh 面板，也不打算做。它只解决一件事：`netsh interface portproxy` 的查看、新增、编辑、删除。

新增的规则类型固定是 `v4tov4`（IPv4 到 IPv4），这也是绝大多数内网转发的实际用法。真要 `v4tov6` 之类的，还是敲命令更直接。

有时候工具的价值不在于覆盖多少功能，而在于把某一件事做到不用思考。三条命令记不住，那就让它变成一个能看见的列表。
